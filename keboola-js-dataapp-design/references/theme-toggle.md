# Light / dark theme toggle

Every report ships with a ☀/☾ toggle in the sidebar header. The choice is
remembered per browser in `localStorage`.

**Default theme:** Economia reports open in **light** (house standard since
2026-10-22, see SKILL.md → Economia house standards). An app that already
shipped dark before the toggle existed may keep `DEFAULT_THEME = 'dark'`, so
its users see no change until they click. The default lives in exactly two
places — `src/theme.ts` and the no-flash script in `index.html` — keep them
in sync.

Proven on "Yield Reports" (project 708, config `01m3rrha312nvcxp6fz9d0hwfk`),
2026-10-21: converting the whole app touched ~12 lines of TSX. Nearly all
of the app's ~130 `text-slate-*` / `bg-slate-*` classes stayed exactly as
they were.

## How it works (one idea)

Tailwind's neutral scale (`slate`) and the light accent-text shades
(`indigo-200/300`, `emerald-300/400`, `rose-200..400`, `amber-200/300`,
`purple-400`) are remapped to CSS variables. The dark values are Tailwind's
own palette. The light values **invert the slate scale** (`slate-900` card
backgrounds become white, `slate-200` text becomes near-black) and darken the
accent text. Switching `<html data-theme>` flips every existing class at
once, so component code is not rewritten.

## 1. `tailwind.config.js`

```js
// Neutral + accent-text shades resolve to CSS variables (see src/index.css),
// so every existing `text-slate-300` / `bg-slate-900/40` / `text-indigo-300`
// flips with the light/dark theme without touching component classes.
const v = (name) => `rgb(var(--${name}) / <alpha-value>)`;
const scale = (color, keys) => Object.fromEntries(keys.map((k) => [k, v(`${color}-${k}`)]));

module.exports = {
  content: ['./index.html', './src/**/*.{ts,tsx}'],
  theme: {
    extend: {
      colors: {
        brand: { /* unchanged */ },
        ink: v('ink'),
        slate: scale('slate', [50, 100, 200, 300, 400, 500, 600, 700, 800, 900, 950]),
        indigo: scale('indigo', [200, 300]),
        emerald: scale('emerald', [300, 400]),
        rose: scale('rose', [200, 300, 400]),
        amber: scale('amber', [200, 300]),
        purple: scale('purple', [400]),
      },
    },
  },
  plugins: [],
};
```

`extend` merges per shade, so `indigo-400/500` etc. keep Tailwind's fixed
values. Those are used for borders and filled backgrounds, which read fine
in both themes. If the app uses another light accent shade for **text**
(e.g. `text-sky-300`), add it to the list and to both token blocks.

## 2. Tokens in `src/index.css`

`references/index.css` already contains both token blocks
(`:root[data-theme="dark"]` / `[data-theme="light"]`), the `--page-bg`
gradient, `--hairline`, `--chart-grid`, and all Classic-mode classes
converted to `rgb(var(--…))`. Copy it as is. Values are space-separated RGB
channels (`15 23 42`), not hex, so Tailwind opacity modifiers like
`/40` keep working.

When retrofitting an existing app, convert every hard-coded colour in
`index.css` the same way: `#FFFFFF` → `rgb(var(--ink))`,
`rgba(15,23,42,0.6)` → `rgb(var(--slate-900) / 0.6)`,
`rgba(255,255,255,0.1)` borders → `var(--hairline)`, the body gradient →
`var(--page-bg)`.

## 3. `text-white` → `text-ink`

`text-white` stays white in light mode and disappears on a white card. Swap it
to `text-ink` (white in dark mode, near-black in light mode) for headings,
KPI values and hover states (`hover:text-white` → `hover:text-ink`).
**Keep** `text-white` where the background is a solid colour
(`bg-gradient-to-r from-brand-primary …`, `bg-indigo-500/80`, active nav item).

```bash
grep -rn 'text-white' src --include=*.tsx
```

## 4. Charts (Recharts)

Recharts sets colours as SVG presentation attributes (`stroke="#1E293B"`), and
`var()` is unreliable there. Two tricks avoid a JS theme context:

- **Tooltip**: `contentStyle` / `itemStyle` / `labelStyle` are inline HTML
  styles, so CSS variables work directly:

  ```ts
  export const tooltipStyle = {
    contentStyle: { background: 'rgb(var(--slate-900))', border: '1px solid rgb(var(--slate-700))', borderRadius: 12, fontSize: 12 },
    itemStyle: { color: 'rgb(var(--slate-200))' },
    labelStyle: { color: 'rgb(var(--slate-200))' },
  };
  ```

- **Grid and cell strokes**: a CSS rule beats a presentation attribute, so
  `.recharts-cartesian-grid line { stroke: var(--chart-grid); }` overrides
  `<CartesianGrid stroke="#1E293B" />`. For custom SVG (e.g. a Treemap cell),
  drop the hard-coded `stroke` and give it `className="treemap-cell"`.

**Trap:** put these rules **outside** `@layer components`. Tailwind purges
layered rules whose selectors never appear in `src/`. `recharts-cartesian-grid`
is generated by Recharts, so a layered rule silently vanishes from the build
and the grid stays dark-grey in light mode. (`references/index.css` already
places them at the end, outside the layer.)

Series colours (`SERIES`, `COLORS`) stay the same in both themes. Check that
very light series (e.g. `#9CC3E6` dashed comparison lines) are still visible
on white.

## 5. `src/theme.ts`

```ts
import { useEffect, useState } from 'react';

// Light/dark theme. The value lives on <html data-theme>, which index.html sets
// before first paint (no flash); colours themselves are CSS variables in index.css.
export type Theme = 'dark' | 'light';
const KEY = '<app-slug>-theme';
// Economia reports start light; use 'dark' only for an app that already shipped dark.
export const DEFAULT_THEME: Theme = 'light';

function current(): Theme {
  const t = document.documentElement.dataset.theme;
  return t === 'dark' || t === 'light' ? t : DEFAULT_THEME;
}

export function useTheme(): [Theme, () => void] {
  const [theme, setTheme] = useState<Theme>(current);
  useEffect(() => {
    document.documentElement.dataset.theme = theme;
    try {
      localStorage.setItem(KEY, theme);
    } catch {
      // storage blocked: theme still applies for this visit
    }
  }, [theme]);
  return [theme, () => setTheme((t) => (t === 'dark' ? 'light' : 'dark'))];
}
```

## 6. `index.html` — apply before first paint

Without this the page renders in the wrong theme for a frame and then flashes.

```html
<script>
  // Apply the saved theme before first paint (default: light, = DEFAULT_THEME in src/theme.ts).
  try {
    var saved = localStorage.getItem('<app-slug>-theme');
    document.documentElement.dataset.theme = saved === 'dark' || saved === 'light' ? saved : 'light';
  } catch (e) {
    document.documentElement.dataset.theme = 'light';
  }
</script>
```

Use the same `<app-slug>-theme` key in both places.

## 7. The button (sidebar header, `src/App.tsx`)

```tsx
import { Sun, Moon } from 'lucide-react';
import { useTheme } from './theme';

const [theme, toggleTheme] = useTheme();

<div className="px-5 py-5 border-b border-slate-800 flex items-start justify-between gap-3">
  <div>{/* eyebrow + app title */}</div>
  <button
    onClick={toggleTheme}
    className="mt-1 rounded-lg border border-slate-700 p-2 text-slate-400 hover:text-ink hover:bg-slate-800/50 transition-colors"
    title={theme === 'dark' ? 'Přepnout na světlý režim' : 'Přepnout na tmavý režim'}
    aria-label={theme === 'dark' ? 'Přepnout na světlý režim' : 'Přepnout na tmavý režim'}
  >
    {theme === 'dark' ? <Sun size={15} /> : <Moon size={15} />}
  </button>
</div>
```

## 8. Verify (both themes, after a full reload)

- Rebuild, then **reload the page**. Hash-route navigation doesn't reload
  the CSS, so checking without a reload shows the old bundle.
- In light mode, check: one chart page (grid light grey, tooltip white),
  one table page (header row light grey, text dark), the treemap if any,
  filter chips and badges.
- Computed-style spot check in the console:
  `getComputedStyle(document.querySelector('.recharts-cartesian-grid line')).stroke`
  → `rgb(226, 232, 240)` in light, `rgb(30, 41, 59)` in dark.
- Toggle to dark and back and confirm both look right (for a retrofitted app
  that was dark before: dark must look identical to before the change).
- Reload: the choice must survive (`localStorage['<app-slug>-theme']`).
